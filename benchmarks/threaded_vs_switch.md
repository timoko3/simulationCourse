# Threaded dispatch против switch

**Результат:** threaded выигрывает на трёх специализированных нагрузках
и немного на CRC32. На сортировке в этой серии быстрее switch.
Эффект зависит от состава инструкций и частоты переходов между блоками.

## Результаты

Ускорение — медиана парных отношений `switch / threaded`; больше `1` означает
преимущество threaded. CI — 95%-й доверительный интервал.

| Workload | Switch ms [95% CI] | Threaded ms [95% CI] | Speedup [95% CI] |
| --- | ---: | ---: | ---: |
| arithmetic | 291.168 [285.536, 300.163] | 185.812 [181.768, 196.174] | 1.549x [1.454, 1.586] |
| branches | 599.428 [574.495, 637.164] | 498.629 [484.437, 516.566] | 1.199x [1.167, 1.243] |
| bubble_sort | 359.437 [341.960, 375.903] | 339.659 [331.889, 344.576] | 1.043x [0.999, 1.087] |
| crc32 | 98.226 [96.436, 100.000] | 92.523 [91.270, 93.512] | 1.058x [1.017, 1.084] |
| insertion_sort | 147.118 [145.794, 149.632] | 145.776 [144.682, 148.341] | 1.000x [0.987, 1.009] |
| memory | 113.489 [112.561, 114.587] | 94.095 [92.730, 95.296] | 1.208x [1.199, 1.233] |

## Оптимизации

| Оптимизации | Как сокращает работу |
| --- | --- |
| Хвостовой переход `clang::musttail` | Обработчики передают управление следующему без создания стековых кадров ( в asm call на jmp заменяется )|
| Обход блока через `iterator` | Убрано копирование блока и инструкций теперь происходит проход по блоку при помощи итератора |
| Общие inline-реализации `exec*` | exec методы вызываемые threaded были в другом cpp в файле, поэтому компилятор без LTO не мог их заинлайнить, а switch находился вместе сними и `exec*`-и спокойно инлайнились. Вынес в отдельный header `exec*`|
| Возвращаемое значение `getBasicBlock()` - ref | Убрал лишнее копирование на каждом вызове функции. |
| Максимально убрал `branches` | 

## Почему эффект различается

- **Arithmetic:** длинные блоки с дешёвыми `ADD`; расходы dispatch занимают
  заметную долю времени, поэтому их сокращение особенно полезно.
- **Branches и memory:** ускорение сохраняется, но часть времени занимает
  обслуживание границ блоков и работа кэша
- **CRC32 и sort:** используется `BEXT`, чья текущая реализация обходит 32 бита.
  CRC32 выполняет два `BEXT` на каждый бит входа; sort использует его для
  сравнения через знак разности. Дорогие операции уменьшают относительную
  пользу от dispatch.

## Условия и проверка корректности

**Среда:** AMD Ryzen 7 8845H, WSL2 / Ubuntu 24.04.5, Clang 18.1.3,
Release `-O3 -DNDEBUG`. Привязка к одному ядру не задавалась.

**Измерение:** один бинарник, 30 пара на нагрузку после двух прогревочных пар;
порядок switch/threaded чередуется. Каждый запуск создаёт новый симулятор
с холодным кэшем декодированных блоков. Таймер охватывает `runSimulation()`;
генерация ELF, загрузка и внешнее сравнение состояния выполняются вне таймера.
CI рассчитан при помощи *bootstrap* метода

**Корректность:** после каждой пары сравниваются регистры, PC и память.
CRC32 дополнительно сверяется с `Zlib.crc32`, сортировка — поэлементно
с результатом Ruby `Array#sort`. Эталоны встроены в ELF.
